# VisionForge AI

**Team T83 · Problem P3 · Resource-efficient text-to-image generation**

VisionForge is a research prototype that compares inference budgets for the pretrained `stabilityai/sd-turbo` model. It exposes 1, 2 and 4 denoising-step profiles and an `auto` resource-aware heuristic, then returns an image with runtime and resource indicators. The project does not train or fine-tune SD-Turbo and does not claim to run on a mobile device.

## Features

- Text-to-image generation at 256, 384 or 512 square resolution.
- Fast (1 step), Balanced (2 steps) and Quality (4 steps) profiles, plus Auto.
- Auto chooses a step budget and may cap resolution using currently available GPU memory or system RAM. It reports the selected profile and reason.
- Same-prompt comparison of a 4-step baseline, a 1-step run and Auto with the same seed and requested size.
- Optional OpenCV post-processing: CLAHE on LAB luminance, bilateral filtering and restrained sharpening.
- CLIP cosine similarity as a relative prompt/image alignment indicator; it is not a probability or a full image-quality score.
- Generation time, CLIP evaluation time, CUDA peak allocated memory when available, and process/system RAM snapshots.
- FastAPI backend and responsive HTML/CSS/JavaScript interface.

## Requirements

- Python 3.10 or newer (Python 3.11 is a practical choice).
- NVIDIA CUDA GPU recommended for usable generation speed. The Docker image targets CUDA 12.1 and PyTorch 2.4.1; for local GPU use, install the PyTorch build that matches the host's supported CUDA version.
- A compatible CPU can run the app, but generation can be very slow. First use downloads the model and CLIP weights from Hugging Face and requires internet access and several gigabytes of free disk space.
- The SD-Turbo model is intended for 512×512 output; smaller sizes are available in this app. Hardware, model loading and system load affect latency.

## Run locally on Windows

Open PowerShell in the repository folder:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 7860
```

Open `http://127.0.0.1:7860`. If PowerShell blocks activation, use `\.venv\Scripts\python.exe -m pip install -r requirements.txt` and `\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 7860` instead. For CUDA, follow the current Windows/Pip/CUDA selector on the [official PyTorch installation page](https://pytorch.org/get-started/locally/) and verify `torch.cuda.is_available()` before starting the app. `MODEL_ID` and `CLIP_ID` can override the defaults; no access token is needed for the public model repositories.

## Run in Google Colab

Open the root-level `Colab_Setup.ipynb` notebook in Colab, select a GPU runtime if available, and follow its cells. The notebook exposes the app on port 7860. Colab runtime availability and session duration depend on the account and current service limits.

The first `GET /health` does not load model weights; it reports the process/device and current resource snapshot. The first generation loads SD-Turbo (and CLIP on evaluation) and may take several minutes, so verify with a real image-generation request.

## Run in Docker

From the repository root:

```bash
docker build -t visionforge .
docker run --rm -p 7860:7860 visionforge
```

Then open `http://127.0.0.1:7860`. The container listens on port 7860. Model files are downloaded on first use and cached in the container's Hugging Face cache; Hugging Face Spaces' default disk is not persistent across restarts, so a restart may require downloading weights again. Do not put tokens in the image or source tree.

## Architecture

1. The browser serves the frontend in `app/static/` and sends JSON requests to FastAPI.
2. `app/main.py` validates inputs, loads SD-Turbo once, and serializes access to shared inference state.
3. Diffusers generates an image with 1, 2 or 4 steps. Auto selects a profile and may reduce output size based on current free resources.
4. Optional OpenCV post-processing runs after generation; it does not guide the diffusion model.
5. CLIP compares text and image embeddings. The API returns a base64 PNG and measurements.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [docs/DESIGN_DOCUMENT.md](docs/DESIGN_DOCUMENT.md) for more detail.

## API

- `GET /health` — process health, model identifier and current device/resource snapshot; it does not load or validate model weights.
- `POST /generate` — accepts a prompt, mode, post-processing flag, optional seed and resolution.
- `POST /compare` — runs a 4-step baseline, a 1-step run and Auto sequentially with the same prompt and seed.

Example request:

```json
{
  "prompt": "A red vintage motorcycle in a rainy Tokyo alley at night, cinematic photograph",
  "mode": "balanced",
  "classical_enhance": true,
  "seed": 42,
  "resolution": 512
}
```

Modes are `fast`, `balanced`, `quality` and `auto`; valid square resolutions are 256, 384 and 512. CUDA peak memory is `null` on CPU. Process RAM fields are snapshots, not peak resident memory. Generation latency excludes initial model loading and CLIP evaluation time.

## Evaluation

The checked-in `visionforge_benchmark.csv` contains three runs for each of Fast, Balanced and Quality. `VisionForge_Final_Evaluation.csv` contains the corresponding summary means and standard deviations. The CSVs do not record the GPU model, run date, software versions, prompt or seed, so the figures cannot establish those details or support broad claims across prompts. In this small sample, reported means are 320.97 ms (Fast), 383.77 ms (Balanced) and 586.87 ms (Quality); reported CLIP scores are 0.3445, 0.3358 and 0.3094, respectively. Treat these as supplied measurements, not independently reproducible benchmark claims.

For a new, documented evaluation against a running server, use:

```powershell
python evaluate.py --url http://127.0.0.1:7860 --repeats 3
```

This performs five prompts × four requested profiles × two post-processing settings, with one warm-up and three measured runs per condition (160 image requests total). It writes raw runs, a JSON summary and a Markdown summary to `evaluation_results/`, which is ignored by Git. Record the GPU/device, CPU/RAM, software versions, model revision, date and commit alongside results. Include human visual review; CLIP cosine is only a relative signal. Do not report PSNR/SSIM without paired reference images.

## Limitations and safety

- This is inference-time budgeting on a pretrained model, not a newly trained mobile model.
- Cloud GPU memory is not phone memory; a server-hosted prototype is not evidence of on-device performance.
- Auto is a heuristic based on current available resources and is not a mobile-device detector.
- Lower step counts can change image quality and prompt alignment; three repeats per mode are not enough to generalize.
- SD-Turbo model-card limitations include weak legible text rendering and imperfect faces/people. Review generated output before presenting it as accurate.
- Check the model card, license and acceptable-use terms before public or commercial use. Generated images can be inaccurate or biased.
